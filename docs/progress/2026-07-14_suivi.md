# Suivi du 14 juillet 2026

## Réalisations

- Tous les modules du pipeline sont écrits.
- L'audit applique les règles de la fiche, journalise chaque vérification et bloque le pipeline dès qu'une règle échoue.
- Les modules d'extraction chargent les limites, la zone, le recensement, le transport, le réseau, les services et les bâtiments. Le fichier du recensement de 6,5 Go est lu par morceaux puis mis en cache.
- Les modules d'analyse calculent les distances, la cote par résidence, l'accès au transport, la demande, la couverture et l'optimisation.
- Le module des ponts détecte les liens qui traversent la rivière, leur retrait chiffre l'effet de barrière.
- Un Dockerfile assure la reproductibilité de niveau 2. Les tests sont verts, ruff et black ne signalent rien.
- Les données réelles confirment 4 municipalités, 387 arrêts fixes, 2 gares, 5 lignes de train et 91 aires de diffusion.

## Décisions prises

- Chaque résidence reçoit une cote sur 100 selon sa distance vers chaque type de service.
- Les aînés de chaque aire de diffusion sont répartis sur les résidences de l'aire.
- Les paliers de distance sont propres à chaque groupe, Excellent sous 200 mètres pour un aîné et sous 400 mètres pour la population générale.
- Deux jeux de poids d'importance guident les cotes, un par groupe. Les deux ne privilégient pas les mêmes services.
- Neuf types de services sont retenus, seule la santé regroupe plusieurs étiquettes.
- Le profil du recensement est mis en cache une seule fois, supprimer le cache force une relecture.
